# Toride を選ぶ理由 {#why-toride}

Toride は、リソース間の関係を考慮する TypeScript 向けの認可エンジンです。認可モデル全体を YAML で定義し、型安全なバインディングを生成して、任意のデータソースと接続できます。データベースは必須ではありません。

## YAML に定義を集約 {#yaml-as-the-single-source-of-truth}

認可モデルを 1 つの YAML ファイルにまとめます。ロール、権限、関係、派生ロール、条件付きルールを、ミドルウェアやデコレーター、アプリケーションコードに分散させず、同じ場所で宣言できます。

```yaml
# policy.yaml — the complete authorization model
version: "1"

actors:
  User:
    attributes:
      id: string
      department: string
      isSuperAdmin: boolean

global_roles:
  superadmin:
    actor_type: User
    when:
      $actor.isSuperAdmin: true

resources:
  Project:
    roles: [viewer, editor, admin]
    permissions: [read, update, delete]

    grants:
      viewer: [read]
      editor: [read, update]
      admin: [all]

    derived_roles:
      - role: admin
        from_global_role: superadmin

      - role: editor
        actor_type: User
        when:
          $actor.department: $resource.department
```

エンジンによるすべての認可判断は、このファイルに基づきます。誰が何をできるかを監査する際は、コードベース全体ではなく YAML を確認できます。

## コード生成による型安全性 {#type-safety-via-codegen}

`@toride/codegen` はポリシーファイルを読み込み、各リソース、ロール、権限、関係の TypeScript 型を生成します。入力ミスや不整合を本番実行前のコンパイル時に検出できます。

```bash
npx toride-codegen policy.yaml -o src/generated/policy-types.ts
```

生成されたコードには、リソース名、ロールのマップ、リゾルバーのシグネチャの型が含まれます。

```typescript
// Auto-generated by @toride/codegen — do not edit

export type Resources = "Organization" | "Project" | "Task";

export interface RoleMap {
  Organization: "member" | "admin";
  Project: "viewer" | "editor" | "admin";
  Task: "viewer" | "editor";
}

export interface PermissionMap {
  Project: "read" | "update" | "delete";
  Task: "read" | "update" | "delete";
}

export interface RelationMap {
  Project: { org: "Organization" };
  Task: { project: "Project"; assignee: "User" };
}
```

YAML でロール名を変更してリゾルバーの更新を忘れた場合も、TypeScript コンパイラーがすぐに知らせます。

## データベースに依存しない設計 {#database-agnostic-by-design}

リゾルバーは、リソース参照を受け取り、属性を返す関数です。インメモリのオブジェクト、REST API、GraphQL エンドポイント、ファイル、データベースなど、データの取得元は自由に選べます。

```typescript
import { Toride, loadYaml } from "toride";
import { readFileSync } from "node:fs";

// Plain objects — no database, no ORM, no infrastructure
const projects: Record<string, any> = {
  "proj-1": { status: "active", department: "engineering" },
};

const engine = new Toride({
  policy: await loadYaml(readFileSync("./policy.yaml", "utf-8")),
  resolvers: {
    Project: async (ref) => {
      const project = projects[ref.id];
      return {
        status: project.status,
        department: project.department,
      };
    },
  },
});
```

エンジンはデータベースの存在を前提としません。リゾルバーを呼び出し、返された属性を使ってポリシーを評価します。

## 関係に基づくポリシー {#relation-based-policies}

YAML ポリシーで深いリソース階層を表現できます。ロールは関係を通じて自動的に伝播します。たとえば Organization の `admin` が、その配下の Project や Task に対しても権限を持つように、手続き的なコードを書かずに定義できます。

```yaml
resources:
  Organization:
    roles: [member, admin]
    permissions: [read, update, manage_projects]

    grants:
      member: [read]
      admin: [all]

  Project:
    roles: [viewer, editor, admin]
    permissions: [read, update, delete, create_task]

    relations:
      org: Organization

    grants:
      viewer: [read]
      editor: [read, update, create_task]
      admin: [all]

    derived_roles:
      # Organization admins are Project admins
      - role: admin
        from_role: admin
        on_relation: org

      # Organization members can view Projects
      - role: viewer
        from_role: member
        on_relation: org

  Task:
    roles: [viewer, editor]
    permissions: [read, update, delete]

    relations:
      project: Project
      assignee: User

    grants:
      viewer: [read]
      editor: [read, update, delete]

    derived_roles:
      # Project editors are Task editors
      - role: editor
        from_role: editor
        on_relation: project

      # Project viewers are Task viewers
      - role: viewer
        from_role: viewer
        on_relation: project

      # Task assignee is an editor
      - role: editor
        from_relation: assignee

    rules:
      - effect: forbid
        permissions: [update, delete]
        when:
          resource.project.status: completed
```

この例は **Organization → Project → Task** の 3 階層を表しています。Organization の admin は、その組織の各 Project では admin、各 Project の Task では editor になります。すべて YAML で宣言されており、エンジンが評価時に関係グラフをたどります。

## 部分評価 {#partial-evaluation}

データソースがデータベースの場合、全レコードを読み込まずに「このユーザーがアクセスできるリソース」を取得したいことがあります。`buildConstraints()` はアクターの属性だけを使ってポリシーを部分的に評価し、WHERE 句へ変換できる制約 AST を生成します。

```typescript
const result = await engine.buildConstraints(actor, "read", "Project");

if (!result.ok) {
  return []; // no access
}

if (result.constraint === null) {
  return await db.project.findMany(); // full access
}

// Translate constraints to a database query
const where = adapter.translate(result.constraint);
return await db.project.findMany({ where });
```

`department: "engineering"` を持つアクターでは、制約 AST が次のような形に簡約されることがあります。

```json
{
  "type": "or",
  "children": [
    { "type": "field_eq", "field": "department", "value": "engineering" },
    { "type": "always" }
  ]
}
```

評価時にアクターの属性は値に置き換えられ、出力にはリソースに関する条件だけが残ります。Toride には [Prisma](/ja/integrations/prisma) と [Drizzle](/ja/integrations/drizzle) のアダプターが用意されています。任意のクエリ言語に対応する `ConstraintAdapter` を実装することもできます。
